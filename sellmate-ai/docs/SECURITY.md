# الأمان في SellMate AI

يوثّق هذا الملف الضوابط الأمنية المطبّقة في المنصّة وأين تُنفَّذ في الكود. الفلسفة: **دفاع متعدّد الطبقات** و**آمن بالإعداد الافتراضي**.

## جدول الضوابط

| المطلب | الحالة | التنفيذ |
|---|---|---|
| Rate limiting (حدود المعدل) | ✅ | `ThrottlerGuard` عام (120/دقيقة) + حدود أشدّ على المصادقة: تسجيل 5/دقيقة، دخول 10/دقيقة، تحديث/خروج 20/دقيقة. |
| Input validation | ✅ | `ValidationPipe` عام (`whitelist`, `forbidNonWhitelisted`, `transform`) + `class-validator` على كل DTO مع حدود طول لكل الحقول والمصفوفات. |
| SQL injection | ✅ | Prisma ORM (استعلامات مُعاملة). لا `$queryRawUnsafe`/`$executeRawUnsafe` في الكود. الاستعلام الخام الوحيد `SELECT 1` للفحص الصحّي بلا مدخلات. |
| XSS | ✅ | API يُعيد JSON فقط + CSP صارم (`default-src 'none'`) + منع رفع SVG/HTML + `nosniff` + CSP مقيّد على مسار `/uploads`. |
| CSRF | ✅ (غير قابل للتطبيق) | المصادقة عبر `Authorization: Bearer` (لا كوكيز جلسة)، فالمتصفّح لا يرفق الرمز تلقائيًا عبر المواقع. CORS محصور بأصل لوحة التحكم. |
| ترويسات HTTP آمنة | ✅ | `helmet`: CSP، HSTS (إنتاج)، `referrer-policy: no-referrer`، منع التأطير، `x-content-type-options`. |
| حماية المصادقة | ✅ | JWT وصول قصير العمر + تدوير رموز التحديث + إبطالها، argon2id، مقارنة ثابتة الزمن، منع كشف الحسابات عبر التوقيت. |
| التخويل (Authorization) | ✅ | `RolesGuard` (OWNER/ADMIN/STAFF) + عزل كل البيانات بنطاق `merchantId` + `PlatformAdminGuard` لإدارة الخطط. |
| التحقق من webhook تيليجرام | ✅ | سرّ لكل متجر عبر ترويسة `x-telegram-bot-api-secret-token` مع **مقارنة ثابتة الزمن** (`timingSafeEqual`). |
| التحقق من طلبات الـ API | ✅ | تحقق صارم بالأنواع + رفض الحقول غير المعروفة + تحويل آمن (لا تحويل ضمني). |
| التحقق من رفع الملفات | ✅ | قائمة أنواع مسموحة (PNG/JPEG/WEBP/GIF) + **تحقق بالبصمة الثنائية** بعد الكتابة + امتداد مُشتقّ من النوع لا من اسم الملف. |
| حدود حجم الملفات | ✅ | 5 ميغابايت للملف الواحد + ملف واحد لكل طلب + حدّ حجم جسم الطلب 1 ميغابايت. |
| أسرار آمنة | ✅ | كل الأسرار من متغيّرات البيئة، تحقق عبر zod، وتشديدات إلزامية في الإنتاج (طول JWT، إلزام مفتاح التشفير). |
| تجزئة كلمات المرور | ✅ | argon2id بمعاملات OWASP (m=19MiB، t=2، p=1) موحّدة عبر التطبيق. |
| سجلّات التدقيق | ✅ | نموذج `AuditLog` + `AuditService` يسجّل أحداث الدخول/التسجيل/الخروج وتغييرات المستخدمين والاشتراك والخطط وحذف المتجر وإعداد البوت. |
| منع تسريب الأسرار للواجهة | ✅ | لا تُعاد مفاتيح API/رموز البوت/بيانات القاعدة/أسرار JWT في أي استجابة. `getConfig` يُعيد `tokenSet: true` فقط. |
| معالجة الأخطاء | ✅ | فلتر استثناءات موحّد؛ لا يُعاد أي stack trace أو تفاصيل داخلية للعميل، ومعرّف تتبّع لأخطاء الخادم. |

## تفاصيل مهمّة

### المصادقة وكلمات المرور
- التجزئة عبر argon2id بمعاملات مضبوطة في `src/common/security/argon2.ts`.
- تسجيل الدخول يُجري تحققًا من تجزئة (حقيقية أو **وهمية** عند غياب المستخدم) لتوحيد زمن الاستجابة ومنع كشف وجود الحساب عبر التوقيت (`auth.service.ts`).
- رسالة دخول واحدة عامة لكل حالات الفشل.
- سياسة قوة كلمة المرور موحّدة عبر `@IsStrongPassword()` (8–128 حرفًا، حرف ورقم على الأقل).
- رموز JWT الوصول قصيرة العمر (900ث افتراضيًا)، ورموز التحديث تُدوَّر وتُبطَل عند الاستخدام والخروج.

### حدود المعدل
- عام: `THROTTLE_LIMIT`/`THROTTLE_TTL` (افتراضي 120/60ث).
- نقاط المصادقة مشدّدة عبر `@Throttle` لكل مسار.
- `trust proxy` مضبوط للحصول على IP الحقيقي خلف وكيل عكسي (يفيد الحدود والتدقيق).

### رفع الملفات (XSS مخزّن)
- يُقبل نوع الصورة من قائمة بيضاء، ثم يُتحقَّق من **البصمة الثنائية الفعلية** على القرص؛ وأي ملف لا يطابق صورة نقطية يُحذف فورًا.
- الامتداد المخزَّن يُشتقّ من النوع المُتحقَّق منه، لا من اسم الملف الأصلي (منعًا لـ `.svg`/`.html`).
- مسار `/uploads` يُخدَم مع `X-Content-Type-Options: nosniff` و`Content-Security-Policy: default-src 'none'; sandbox`.
- في الإنتاج يُفضَّل تخزين سحابي (S3) مع نطاق منفصل للأصول.

### سجلّ التدقيق
- النموذج `AuditLog` **بلا مفتاح خارجي** للمتجر عمدًا، لتبقى السجلّات محفوظة حتى بعد حذف المتجر.
- التسجيل «أفضل جهد»: فشل التدقيق لا يُعطّل العملية الأساسية.
- **لا تُسجَّل أسرار** (رموز البوت/كلمات المرور) في التدقيق إطلاقًا.
- القراءة عبر `GET /api/v1/audit-logs` (OWNER/ADMIN فقط، محصورة بنطاق المتجر).

### معالجة الأخطاء
- فلتر موحّد في `src/common/filters/all-exceptions.filter.ts`.
- لأخطاء الخادم (≥500): معرّف تتبّع (`requestId`) يُسجَّل داخليًا ويُعاد للعميل مع رسالة عامة فقط — **دون stack trace أو تفاصيل Prisma/داخلية**.
- لا كشف لأسماء الأعمدة في تعارض التكرار (P2002).

## قبل النشر في الإنتاج
1. `NODE_ENV=production` يفرض: `JWT_SECRET` ≥ 32 حرفًا، `ENCRYPTION_KEY` إلزاميًا (base64 لـ 32 بايت)، `TELEGRAM_WEBHOOK_SECRET` ≥ 16 حرفًا.
2. اضبط `PLATFORM_ADMIN_EMAILS` بحذر (يتحكّم بتعديل أسعار الخطط).
3. شغّل خلف HTTPS ووكيل عكسي (HSTS يعمل عبر HTTPS).
4. طبّق الهجرات: `prisma migrate deploy` ثم `prisma generate` (يلزم لتوليد نوع `AuditLog`).
5. راجع أصول CORS في `APP_URL`/`CORS_ORIGINS`.
